c. DESIGN DECISIONS / RATIONALE
-------------------------------
  - SAFETY BY DEFAULT: writes are OFF unless ADMIN_TOKEN is set AND the service
    account has Editor. Read-only deploys are unaffected (read path still uses the
    .readonly scope; only the write route requests the broader scope).
  - MINIMAL, TARGETED WRITES: only the live-changing fields are managed
    (item: currentBid/highBidder/lastBidTime/closeTime; ticket: same +
    cascadeStart; config: eventName + the *seconds* timing keys + featuredItemId).
    Name/description/image/winner-phone/paid columns are never touched.
  - ROW MATCHING: items by ID (falls back to name, mirroring the reader); tickets
    by group+label. A payload row not found is REPORTED (unmatched), never
    appended — avoids duplicate rows on a live sheet. Same for missing columns
    (skipped) and missing config keys (skipped, not appended).
  - TIME ROUND-TRIP: write human-readable local times ("7/18/2026 5:31:00 PM")
    with RAW input so Sheets stores them as text and parseSheetTime reads them
    back to the identical instant. Verified by a test.
  - FOOTGUN GUARD: the console can simulate bids + fast-forward; those values are
    what gets saved. Mitigations: explicit confirm() dialog, a clear panel note,
    and the documented "Reload from source first" flow.

    instead of the words "up next/closing" — directly honoring the sheet times.

(b) PER-TICKET CLOSE TIMES — lib/auction.ts (computeTicketGroup)
  - THE KEY CHANGE. Two modes now, chosen automatically by DISTINCT cascade-start
    count in the group:
      * >= 2 distinct times  -> PER-TICKET MODE: each ticket closes at its own
        listed time (anti-snipe applied per ticket), ordered soonest-first.
      * 0 or 1 distinct time -> CASCADE MODE (unchanged legacy): one group start,
        highest bid first, each ticket = previous + ticketCountdownSeconds, so a
        late bid pushes all remaining out together.
  - Detection is by DISTINCT value on purpose: demo.ts sets the SAME start on
    every row of a group (that's a group start, must stay cascade) whereas the
    user's sheet sets a DIFFERENT time per row (per-ticket). Helper
    distinctStartCount() + comparator compareTicketTimes() added.
  - Backward compatible: legacy cascade tests and the per-group-start test still
    pass; demo still cascades.
  - Tradeoff: in PER-TICKET MODE the "a bid extends ALL remaining tickets" rule
    does NOT apply (only per-ticket anti-snipe) — explicit times are independent.
    The original cascade extend-all still works in CASCADE MODE. If the user
    wants extend-all WITH explicit per-ticket times, that's a future option.
