c. DESIGN DECISIONS / RATIONALE
-------------------------------
  - SAFETY BY DEFAULT: writes are OFF unless ADMIN_TOKEN is set AND the service
    account has Editor. Read-only deploys are unaffected (read path still uses the
    .readonly scope; only the write route requests the broader scope).
  - MINIMAL, TARGETED WRITES: only the live-changing fields are managed
    (item: currentBid/highBidder/lastBidTime/closeTime; ticket: same +
    cascadeStart; config: eventName + the *seconds* timing keys + featuredItemId).
    Name/description/image/winner-phone/paid columns are never touched.
  - ROW MATCHING: items by ID (falls back to name, mirroring the reader); tickets
    by group+label. A payload row not found is REPORTED (unmatched), never
    appended — avoids duplicate rows on a live sheet. Same for missing columns
    (skipped) and missing config keys (skipped, not appended).
  - TIME ROUND-TRIP: write human-readable local times ("7/18/2026 5:31:00 PM")
    with RAW input so Sheets stores them as text and parseSheetTime reads them
    back to the identical instant. Verified by a test.
  - FOOTGUN GUARD: the console can simulate bids + fast-forward; those values are
    what gets saved. Mitigations: explicit confirm() dialog, a clear panel note,
    and the documented "Reload from source first" flow.
