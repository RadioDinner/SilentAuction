b. THE CASCADE REWORK (re-applied onto main)
--------------------------------------------
Clarified rules (user Q&A):
  1. MORE BIDS THAN SEATS. A group has a fixed seat count (e.g. 12) but can take
     more bids than seats. Bids ranked highest-first; top `seats` hold a seat and
     cascade-close, lower bids are "outbid". Default seats = #bids, so a group
     with no Seats set behaves exactly as before (everyone wins).
  2. NEW HIGH BID TAKES TOP, OLD CASCADES DOWN. A higher bid re-sorts to the top
     (active/closing seat); the bid it beat slides down to fight for the next
     seat, shoving each lower bid down one; the lowest seat-holder drops to
     "outbid". Pure re-rank every poll — no stored state.
  TIE-BREAK: ties now break by TICKET NUMBER (label), not bid time, so raising a
     bid never changes tie-break priority. Reproduces the brief's Sales Office
     Lunch order: $70->1; $50->2,5; $40->10; $30->3,11,12; $20->4,6,7,8,9.

  Integration note: main's computeTicketGroup has TWO modes. Seats/outbid apply
  in CASCADE mode (one shared start, bid-ranked). PER-TICKET mode (each row has
  its own distinct close time) is untouched — every ticket keeps its seat there.

ADDENDUM 3 — bid extends the Now Closing timer, no write-back
------------------------------------------------------------
- User wants a bid to push the active card out ~1 min (chose "reset to 1:00 from
  each bid"), with NOTHING written to the Google Sheet.
- Root cause it "didn't update": the display-only anti-snipe (close = max(
  scheduled, lastBid + window)) was already correct, but it needs a bid TIME.
  The user edits Current Bid directly and most "Last Bid Time" cells are blank,
  so the engine had no timestamp -> no extension.
- Fix (no sheet writes): lib/bid-memory.ts — a server-side, in-memory detector.
  app/api/state/route.ts calls observeBid() per row (sheet path); when a
  Current Bid goes UP it stamps "now" as the bid time (sticky until the next
  increase), feeding the existing anti-snipe. So a bid now extends the active
  card to 1 min with no write-back and no dependency on Last Bid Time / the
  onEdit Apps Script. Last Bid Time is still honored if present (max of the two).
  +4 unit tests (lib/bid-memory.test.ts). 62 tests pass; build clean.
- INHERENT (explained to user): because close = "bid time + 1 min, or scheduled
  if later", a bid only visibly moves the timer in the final minute; earlier bids
  leave the scheduled time in place. To see it while testing, fast-forward the
  admin clock to the final minute before bidding.
- CAVEAT (documented): the memory is per server instance and non-durable; a
  redeploy/cold start resets the baseline (and would drop an in-flight
  extension). Fine for a one-day single-endpoint event.
